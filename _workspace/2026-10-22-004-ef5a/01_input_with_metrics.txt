# 진단

## 장르·레지스터

- 장르: essay. 1,000자 이내 자기소개서 문항 답변이며 원문은 834자다.
- 레지스터: 합쇼체. 수행한 일과 판단 근거를 차분히 설명하는 문체를 유지한다.
- 전체 판단: 정량 risk_band는 low(score 3)다. 경험의 구체성이 충분하므로 대대적인 재작성보다 아래 세 패턴을 국소적으로 다듬는 편이 적합하다. 점수와 z값만으로 AI 작성 여부를 판정하지 않는다.

## 겨냥 순서의 지배 패턴

1. **C-11 — 연결어미 뒤 쉼표.** “정리하고, AI가”, “높이고, 반복적인”, “받았으며, 설계”처럼 연결어미 뒤 쉼표가 반복된다. 이미 연결어미로 이어진 절을 다시 구획하면서 설명을 일정한 박자로 끊는다. 의미상 쉼표가 필요한지 먼저 판단한다.
2. **A-18 — 긴 좌향 수식·관형절 밀집.** 정량 블록의 `relative_clause_nesting`이 2이므로 본진 A-18을 검토 대상으로 확정한다. 특히 “플레이 가능한 게임 흐름과 전투 연출을 구현하는 한편, AI와 협업하는 절차도 재사용할 수 있게”는 관형형과 설명 절이 한 문장에 겹친다. 다만 이 지표는 문장 내 관형형을 세는 근사치이므로 실제 3중 중첩을 확정하는 근거로 확대하지 않는다. 수식의 실제 부담을 살펴 국소적으로 덜어낸다.
3. **E-5 — 긴 쉼표 분절.** “변경 범위 확인과 작성 양식, 팀원 리뷰 요청까지”와 마지막 두 문장의 긴 절에서 여러 작업·성과·판단을 함께 회수한다. 쉼표만 지우면 문장 안의 부담이 남을 수 있으므로 호흡과 정보 배치도 함께 살핀다. C-11이 쉼표의 문법적 위치 문제라면 E-5는 쉼표 양옆 절의 길이 문제다.

## 정량 앵커

- `ending_comma_rate`: 0.43, essay baseline 대비 z=+4.93. C-11 우선 검토 근거다.
- `comma_segment_length`: 9.10, z=+2.25. E-5 검토 근거다.
- `relative_clause_nesting`: 2. A-18 검토 근거이며 휴리스틱의 한계를 감안한다.
- `comma_inclusion_rate`: 0.40. C-12의 50% 초과 조건에 해당하지 않으므로 문서 전체의 쉼표 과다로 진단하지 않는다.
- 이중 피동·by 피동·부적절한 대명사·have/make 직역·이중 조사 카운트는 모두 0이다. 해당 패턴을 추가하지 않는다.

## 구조·리듬·결말 검토

- 이항 대구나 “A가 아니라 B” 구조의 반복은 없다.
- 문단은 3~4문장으로 비슷하지만 도구 설정→전투 연출→반복 업무 정리의 경험 흐름이 분명하다. 문단 수를 억지로 바꿀 필요는 없다.
- 합쇼체 어미가 이어지는 것은 자기소개서 문체에 맞는다. 어미 다양화를 위해 해요체·한다체를 섞지 않는다.
- 마지막 문장은 AI의 구현 기여와 본인의 설계·검증 책임을 구분한다. 관행적인 포부나 성찰 문장으로 바꾸지 않는다.
- “개발 환경과 진행 절차”, “구조 설계와 영향 범위 검토” 같은 명사구는 있으나 행동과 사례가 뒤따른다. 추상명사 과다를 지배 패턴으로 확대하지 않는다.

## 보존 지침

- Unity 전략 퍼즐 게임 ‘Re:bellion’, Codex와 Unity MCP, 코드·씬·프리팹 확인이라는 구체 정보를 보존한다.
- 추론 강도 조절, 반복 작업의 하위 모델 배정, 에이전트 작업 범위와 재귀 생성 제한, 단계별 본인 검토를 보존한다.
- “전투가 밋밋하다”는 피드백, 전투 판정·연출 분리, 카메라 포커싱·히트스톱, 직접 플레이한 뒤의 조정 과정을 보존한다.
- 커밋·푸시·PR 개인 스킬, 변경 범위·작성 양식·팀원 리뷰 요청 규칙을 보존한다.
- AI가 구현을 도왔고 본인이 설계 방향·검증·최종 반영을 판단했다는 역할과 책임을 유지한다. 성과 수치·기간·팀 규모·새 경험을 덧붙이지 않는다.
- 1,000자 제한을 지키고 자기소개서에 맞는 담백한 합쇼체를 유지한다.

[원문 시작]
Unity 기반 전략 퍼즐 게임 ‘Re:bellion’을 개발하며 AI가 기존 게임 규칙과 구조에 맞춰 작업하도록 개발 환경과 진행 절차를 구성했습니다. 기물 배치부터 전투, 재시도까지 서로 맞물려 있어 기능 하나를 맡길 때도 전체 흐름에 미칠 영향을 살펴야 했습니다. 저는 먼저 기능 간 의존성과 지켜야 할 규칙을 정리하고, AI가 수행할 작업을 검토 가능한 단위로 나눴습니다.

Codex에 Unity MCP를 연결해 코드와 씬·프리팹을 함께 확인하도록 했습니다. 구조 설계와 영향 범위 검토에는 추론 강도를 높이고, 반복적인 Unity 설정과 확인은 하위 모델에 맡겼습니다. 각 에이전트가 어디까지 작업할지 지정하고 재귀 생성도 제한했습니다. 한 단계가 끝나면 제가 결과를 검토해 다음 작업을 정하는 방식으로 진행했습니다.

전투 연출에서는 ‘전투가 밋밋하다’는 피드백을 어떻게 반영할지부터 판단했습니다. 전투 판정과 연출을 분리한 뒤 카메라 포커싱과 히트스톱을 단계적으로 적용하게 했습니다. 이후 직접 플레이하며 공격 흐름이 명확하게 보이는지를 기준으로 카메라 움직임과 타이밍을 조정했습니다. AI가 제안한 효과도 실제 플레이에서 어색하면 수정 방향을 다시 제시했습니다.

이 과정에서 반복하던 커밋·푸시·PR 지시는 개인 스킬로 정리하게 했습니다. 변경 범위 확인과 작성 양식, 팀원 리뷰 요청까지 규칙으로 남겨 이후 작업에도 같은 기준을 적용했습니다. 그 결과 플레이 가능한 게임 흐름과 전투 연출을 구현하는 한편, AI와 협업하는 절차도 재사용할 수 있게 만들었습니다. 구현에는 AI의 도움을 받았으며, 설계 방향을 정하고 결과를 검증해 최종 반영하는 판단은 제가 맡았습니다.
